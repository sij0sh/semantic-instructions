# Details

**Frame.** Read the target and direct references; identify existing rules, evidence, and unresolved questions. Separate requirements from preferences; distinguish facts, assumptions, unknowns, and decisions. Surface consequential ambiguity as a question, not a requirement.

**New.** SKILL.md needs `name`/`description` frontmatter; AGENTS.md is plain markdown; agent definitions follow project shape or surface unknown; prompts are plain text; workflow/evaluation instructions follow surrounding format.

**Instruction kinds.** Semantic directives direct judgment; evaluative questions expose failure; mechanical rules enforce execution. Disclose conditional rules. Use deterministic mechanics for state, ordering, persistence, checkable constraints. A mechanical rule needs trigger, changed decision, observable outcome.

**Challenge.** Sufficiency: name a concrete literal-compliance failure, or a plausible failure with evidence it does not apply; "none found" fails. Necessity: state each rule's behavior change; remove rules changing none; keep semantic directives without mechanical triggers. Revise affected text only, max twice; then report unresolved risk.

**Output.** create/edit/simplify with a path writes; without a path returns only the instruction. New files use required shape; edits preserve format/scope. Review never writes; returns findings and a proposed diff, inline without a path. Written: a short confirmation. Unwritten non-review: only the instruction. Rationale: removed or contested rules and unresolved questions.

**Artifacts.** Workflow stages—what is lost at a boundary? Agent definitions—ownership or contract gap? Evaluations—could a compliant agent pass superficially?
